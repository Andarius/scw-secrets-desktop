# AGENTS.md

SCW Secrets Desktop: desktop UI for browsing and managing Scaleway Secret Manager secrets. A Deno backend
(`src/deno/main.ts`) runs an in-process HTTP server and opens a native webview window; the React frontend
(`src/mainview/`) calls it through a typed client (`src/mainview/lib/rpc.ts`, POST `/api/<method>`, contract in
`src/shared/rpc.ts`).

Setup, workflow, PR and release conventions: see `CONTRIBUTING.md`.

## Stack

- Deno 2.9+ (`deno desktop`, backend runtime), Bun 1.3 (frontend toolchain, unit tests), React, TypeScript,
  Tailwind CSS 3, Vite, Playwright, just.
- The `justfile` hides the bun/deno split; `just --list` for everything.

## Structure

- `src/deno/` — backend: entrypoint, local HTTP API (`http.ts`), Scaleway API client (`scw.ts`)
- `src/shared/` — types (`models.ts`) and API contract (`rpc.ts`) shared by both sides
- `src/mainview/lib/` — frontend logic: API client, settings, value parsing, secret list/version helpers
- `src/mainview/hooks/` — React hooks, one per file (`useXxx.ts`)
- `src/mainview/components/` — grouped by role: `layout/`, `panels/`, `modals/`, `secret-value/`, `inputs/`, `search/`
- `src/mainview/mock/` — mock mode (`just mock`): `MockApp` sample data and the mock API used by e2e tests
- `tests/deno/`, `tests/mainview/` — unit tests (bun test); `tests/e2e/` — Playwright against mock mode

## Verify

Match CI (`.github/workflows/ci.yml`):

```bash
just ci        # typecheck + build + deno check + unit tests + e2e
```

Or piecemeal: `just typecheck`, `just build && just deno-check`, `just test`, `just e2e`.

## Rules linters don't catch

- `src/deno/embed.ts` is generated by `just build` (`deno task embed`) and gitignored; `deno check` needs it in sync.
- The local API is a security boundary: keep the host, token and cross-site checks in `src/deno/http.ts`, and cover
  any change to them in `tests/deno/http.test.ts`.
- Scaleway secret versions are immutable: saving a value creates a new revision. `Secret.version_count` also counts
  versions scheduled for deletion; use the active counts (`useActiveVersionCounts`) for anything user-facing.
- `MockApp` mirrors parts of `App`; when a UI change touches shared state, update both and the mock API so e2e covers it.
- Every UI behavior change comes with a Playwright test in `tests/e2e/mock-app.e2e.ts`.
- Scaleway API reference: there is no public OpenAPI spec. The Go SDK is the most reliable source for endpoints and
  fields: https://raw.githubusercontent.com/scaleway/scaleway-sdk-go/master/api/secret/v1beta1/secret_sdk.go
